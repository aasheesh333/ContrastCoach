# Play Store Compliance (2026)

Critical reference for submitting ContrastCoach to Google Play. Compliant from day one, no rework.

## Required forms in Play Console

1. **Data Safety form** (mandatory for all apps)
2. **Health Apps declaration** (mandatory for health apps)
3. **AI-generated content disclosure** (only if using LLM)

## Data Safety form (paste-ready)

### Disclosed data

| Data Type | Collected | Shared | Purpose | User Control |
|---|---|---|---|---|
| Email address | Yes | No | Account creation | Delete account |
| App interactions | Yes (5 events) | No | Improve app | Opt-out in Settings |
| Health info (HR, HRV, sleep) | Yes (local only) | No | Recovery score | Disconnect Health Connect |
| Crash logs | Yes | No | Fix bugs | Cannot opt-out (no PII) |
| Purchase history | Yes | No | Subscription mgmt | Delete account |

### NOT collected

- Device ID
- Location
- Contacts
- Photos
- Voice recordings (processed, not stored)
- Files
- Calendar

### Security practices

- Data in transit: HTTPS/TLS 1.3
- Data at rest: SQLCipher encryption
- User can request data deletion: yes
- User can request data export: yes
- Data deletion timeframe: 30 days

## Health Apps declaration (paste-ready justifications)

### Heart Rate (READ)

> Purpose: Calculate session intensity and recovery response.
> Core feature: Yes. Without HR data, the recovery score cannot account for cardiovascular response to contrast.
> Justification: Contrast therapy's main effect is cardiovascular — alternating vasodilation/vasoconstriction. HR data is essential.

### HRV (READ)

> Purpose: Calculate weekly stress/recovery trend. Display in monthly Insights.
> Core feature: Yes. HRV is the gold-standard recovery biomarker.
> Justification: HRV trend is the single most validated recovery metric. Without it, the recovery score would be speculative.

### Sleep (READ)

> Purpose: Correlate contrast sessions with next-day sleep quality. Display in Insights.
> Core feature: Yes. Sleep is a primary outcome measure.
> Justification: Users want to know "is contrast therapy actually helping my sleep?" — without sleep data, unanswerable.

### Mindful Session (WRITE)

> Purpose: Log contrast therapy session as wellness activity.
> Core feature: Yes. Most basic logging function expected.
> Justification: Writing one entry per session is the minimum users expect.

### Resting Heart Rate, Steps, Exercise (READ)

> Purpose: Provide activity context for protocol recommendations.
> Core feature: Partial. Used only for "good time to do contrast" suggestions.
> Justification: Knowing user's recent activity level allows smarter timing recommendations.

## AndroidManifest declarations (required)

```xml
<uses-permission android:name="android.permission.health.READ_HEART_RATE"/>
<uses-permission android:name="android.permission.health.READ_RESTING_HEART_RATE"/>
<uses-permission android:name="android.permission.health.READ_HRV"/>
<uses-permission android:name="android.permission.health.READ_SLEEP"/>
<uses-permission android:name="android.permission.health.READ_STEPS"/>
<uses-permission android:name="android.permission.health.READ_EXERCISE"/>
<uses-permission android:name="android.permission.health.WRITE_MINDFULNESS"/>

<queries>
  <package android:name="com.google.android.apps.healthdata" />
</queries>

<activity-alias
    android:name="ViewPermissionUsageActivity"
    android:targetPackage="${applicationId}"
    android:targetClass=".health.PermissionUsageActivity"
    android:exported="true">
    <intent-filter>
        <action android:name="androidx.health.ACTION_VIEW_PERMISSION_USAGE" />
        <category android:name="android.intent.category.DEFAULT" />
    </intent-filter>
</activity-alias>
```

## Medical disclaimer placement

Must appear in:
- Onboarding (step 1 or 2)
- Settings → About
- Before any "advice" (Insights, recovery score explanation)
- Paywall (before purchase)
- In app description (store listing)

Recommended text:
> This app is for informational and educational purposes only. It is not a medical device. Consult a healthcare professional before starting any new recovery routine.

## AI-generated content (we don't use it)

ContrastCoach uses deterministic algorithms, not LLM. No disclosure required.

If we add AI later (e.g., GPT-generated insights):
- Disclose "AI-generated insights" in app description
- Add visible label: "This insight was generated by AI"
- Implement content filters (no medical advice)
- Proactive safety measures

## Common rejection reasons (avoid)

1. **Health permission not justified** → Fill Health Apps Declaration thoroughly
2. **Data Safety form doesn't match behavior** → Audit every SDK and data flow
3. **Privacy policy inaccessible** → HTTPS, public, loads fast
4. **Unnecessary permissions** → Only request what you actively use
5. **Medical claims without disclaimer** → Add prominent "Not medical advice"
6. **App doesn't work without Health Connect** → Make it optional, core works without
7. **Health data sent to server** → Don't. Document in privacy policy.
